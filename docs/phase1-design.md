## 二、世界地图生成

### 2.1 地图规格
| 参数 | 值 | 说明 |
|------|------|------|
| 地图尺寸 | 200 × 200 tiles | 每个 tile 32×32 像素，总地图 6400×6400 像素 |
| Tile 尺寸 | 32 × 32 px | 标准像素 Tile |
| 视口显示 | 约 40 × 22 tiles | 在 1280×720 窗口下可见范围 |

### 2.2 地形类型与颜色（占位阶段）
初期使用纯色块占位，不画实际像素素材：

| 地形类型 | 颜色（占位） | 灵气浓度 | 说明 |
|----------|-------------|----------|------|
| 深水 | #1a3a5c | 0 | 不可通行 |
| 浅水 | #2a6aa6 | 0 | 不可通行 |
| 沙地 | #c2b280 | 低 | 可通行，速度慢 |
| 平原 | #4a8c3f | 低 | 可通行 |
| 草地 | #3a7d32 | 低 | 可通行 |
| 森林 | #2d5a27 | 中 | 可通行，速度慢 |
| 山地 | #6b6b6b | 中 | 可通行，速度慢 |
| 高山 | #4a4a4a | 0 | 不可通行 |
| 灵脉 | #9b59b6（发光） | 极高 | 特殊区域 |
| 沼泽 | #3d5c3a | 低 | 可通行，速度慢 |
| 宗门驻地 | #d4a843（标记） | 高 | 特殊区域 |
| 凡人聚落 | #8b7355 | 低 | 特殊区域 |

### 2.3 地形生成算法

采用多层噪声叠加生成自然地形：

```
步骤 1：基础高度图
  - 使用 FastNoiseLite（Fractal 类型）
  - noise_type = NoiseType.TYPE_SIMPLEX
  - fractal_type = FractalType.FBM
  - frequency = 0.01（控制地形变化频率）
  - fractal_octaves = 5（层数越多细节越丰富）

步骤 2：温度图（第二层噪声）
  - 使用独立的 FastNoiseLite 实例
  - frequency = 0.008（比高度图更平缓）
  - 用于决定区域是寒冷还是温暖

步骤 3：湿度图（第三层噪声）
  - 使用独立的 FastNoiseLite 实例
  - frequency = 0.012
  - 用于决定区域是干燥还是潮湿

步骤 4：地形判定
  - 根据高度、温度、湿度三个值组合判定地形类型
  - 高度 < 0.3 → 水域
  - 高度 0.3-0.4 + 高湿度 → 沼泽
  - 高度 0.4-0.5 + 低湿度 → 沙地
  - 高度 0.4-0.6 → 平原/草地
  - 高度 0.5-0.7 + 高湿度 → 森林
  - 高度 0.7-0.85 → 山地
  - 高度 > 0.85 → 高山（不可通行）

步骤 5：灵脉生成
  - 在高度图基础上，使用第四层噪声（频率较低）
  - 高灵气噪声值 > 0.7 且 非水域/非高山的区域 → 灵脉

步骤 6：宗门驻地放置
  - 在灵脉附近（距离灵脉 3-8 tiles）放置宗门驻地
  - 确保宗门之间最小距离 ≥ 30 tiles
  - 宗门数量根据地图大小动态决定（约 5-8 个）

步骤 7：凡人聚落放置
  - 在平原/草地上随机放置
  - 避开水域、高山、宗门驻地
  - 数量约 10-15 个
```

### 2.4 灵气浓度

每个 tile 拥有一个灵气浓度值（0-100），影响修炼效率：

```
灵气浓度计算：
  基础值 = 根据地形类型设定（见上表）
  修正 = 灵脉加成（距离灵脉越近越高，衰减半径约 10 tiles）
  最终灵气 = clamp(基础值 + 灵脉修正, 0, 100)
```

### 2.5 TileSet 方案
- Phase 1 使用 **程序化 TileMap**：不制作 TileSet 素材，而是用 `TileMapLayer` 的 `set_cell()` 直接设置每个 tile 的颜色
- 使用一个 32×32 的纯色 `Texture2D` 作为基础 tile，通过 `modulate` 改变颜色来表示不同地形
- 后续 Phase 6 再替换为正式的像素素材

## 三、地图交互（相机控制）

### 3.1 拖拽移动
- 按住鼠标中键 / 左键拖拽地图
- 使用 `Camera2D` 节点，通过调整 position 实现平移
- 移动范围限制在地图边界内

### 3.2 滚轮缩放
- 鼠标滚轮缩放，以鼠标所在位置为中心
- 缩放范围：0.25x ~ 3x
- 使用 `Camera2D.zoom` 控制
- 保持像素风格：缩放值仅使用整数倍或 0.5 步进（0.5, 1.0, 1.5, 2.0, 3.0）

### 3.3 键盘快捷键
| 按键 | 功能 |
|------|------|
| WASD / 方向键 | 平移地图 |
| 空格 | 暂停/继续时间 |
| 1/2/3 | 时间速度 1x/2x/5x |
| ESC | 取消选择 / 关闭面板 |

## 四、时间系统

### 4.1 时间模型
- 世界时间以「年」为基本单位
- 每年分为 4 个季度：春、夏、秋、冬
- 内部以 tick 计时：1 tick = 0.1 年（约 36 天）
- 游戏时间与真实时间的关系（1x 速度下）：

| 速度 | 真实时间 1 秒 = 游戏时间 | 真实时间 1 分钟 = 游戏时间 |
|------|-------------------------|-------------------------|
| 暂停 | 停止 | 停止 |
| 1x | 0.5 年 | 30 年 |
| 2x | 1 年 | 60 年 |
| 5x | 2.5 年 | 150 年 |

> 这个节奏可以后续调整，当前设定让玩家在 1x 下 1 分钟能看到 30 年的变化，修士的一生可以在几分钟内观察完。

### 4.2 时间管理器（GameTime）
```
GameTime (AutoLoad):
  属性：
    - current_tick: int          # 当前 tick
    - current_year: int          # 当前年
    - current_season: String     # 当前季节
    - speed: int                 # 1=暂停, 2=1x, 3=2x, 4=5x
    - timer: Timer               # 节拍计时器

  信号：
    - tick_passed(tick, year, season)  # 每 tick 触发
    - year_passed(year)                # 每年触发
    - speed_changed(speed)             # 速度变更时触发

  方法：
    - pause()              # 暂停
    - resume()             # 恢复到 1x
    - set_speed(speed)     # 设置速度
    - get_date_string()    # 返回 "第X年 春/夏/秋/冬" 格式字符串
```

### 4.3 季节对地图的影响（Phase 1 简单实现）
- 春/夏季：地图颜色偏绿
- 秋季：森林/草地颜色偏黄
- 冬季：高海拔区域变白（雪），整体颜色偏冷
- 通过 `modulate` 调整 TileMap 的颜色叠加层实现，不重新生成地图

## 五、基础 UI 框架

### 5.1 顶部信息栏（TopBar）
```
┌──────────────────────────────────────────────┐
│ 📅 第123年 春季    ⏱ 1x    ✦ 天机值: 100   │
└──────────────────────────────────────────────┘
```
- 左侧：当前年 + 季节
- 中间：当前时间流速
- 右侧：天机值（Phase 5 实现具体功能，Phase 1 先显示）

### 5.2 时间控制栏（TimeControl）
```
┌────────────────────────┐
│  ⏸  ▶1x  ▶▶2x  ▶▶▶5x  │
└────────────────────────┘
```
- 底部居中，四个按钮：暂停 / 1x / 2x / 5x
- 当前选中的速度高亮显示
- 空格键快捷暂停/恢复

